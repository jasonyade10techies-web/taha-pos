## Tests and audit execution boundary

- `server/package.json` defines `test` as `tsx --test --test-concurrency=1 test/*.test.ts`. This includes PostgreSQL integration suites that create/drop isolated databases; it is not a pure unit-test command. Several tests require the dedicated loopback fixture on port 55459, and some retain a default URL. Main audit owns any isolated DB execution.
- Existing test sources cover smart-service permissions/rollback/concurrent stock and duplicate retries (`smart-services.test.ts`), compound floor/tax/product-only/credit rounding (`compound-services.test.ts`), multi-box classified material return/void (`damaged-inventory.test.ts`), and cash restart/lost-ack/refund/post races (`cash-reconciliation.test.ts`). This audit **read** those cases, it did not report them as passing.
- Cloud media test sources use an HTTP S3-compatible contract fixture, local fake objects and isolated PostgreSQL; `browser-direct-upload.test.ts` uses a provider boundary fixture. They do not establish real private bucket CORS, restart retention or external HTTPS behavior. They cannot substitute for the missing implementation.
- Fresh read-only execution: byte/NUL/source inventory; SHA-256; actual `serviceInput` import using `node --import tsx` with a synthetic null-link input (result above). No SQL or external service was invoked by that validator probe. Early shell-quoting/REPL attempts did not execute the intended probe; the later successful process exited 0.
- No source fix was applied. Recovery of the original MediaService from trustworthy backup/version history, followed by build and isolated regression, is the first dependency before accepting this backend again. Native hardware, provider credentials/resources and live deployment are separate gates.
